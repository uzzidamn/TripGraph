## Unspecified Decisions Made During Build

### ToastContainer exported from Toast.jsx (not a separate file)
The spec implied a `ToastContainer` component. Placed it in `Toast.jsx` alongside `ToastItem`
rather than a separate `ToastContainer.jsx` to keep related render logic in one file.
`App.jsx` imports `{ ToastContainer }` from `./components/ui/Toast`.

### Leaflet marker icons fixed with mergeOptions
Vite bundlers break Leaflet's default marker icon resolution (`_getIconUrl`). Added
`delete L.Icon.Default.prototype._getIconUrl` + `mergeOptions` with absolute unpkg CDN URLs
for the 3 icon files. This is the standard Leaflet-in-Vite fix.

### Custom SVG pin icons keyed by point type
Instead of uniform markers, `MapView` generates inline SVG pins coloured by type
(origin=purple, destination=teal, waypoint=yellow, hotel=green, activity=orange).
Avoids any extra icon library dependency.

### CalendarView uses pixel-percentage layout (no time-grid library)
Event blocks are positioned with `left: ((startMin - DAY_START) / TOTAL_MINS) * 100%`
CSS. Simpler than a full calendar library and sufficient for the 6 AM – 11 PM window.

### AnimatePresence mode="wait" for page transitions
Ensures the outgoing page fully exits before the incoming page enters, avoiding
z-index stacking artefacts across the 3-step flow.

### Example chat presets in ChatRoom
Two "Try:" buttons (Rishikesh / Jaipur) allow a zero-typing demo without the backend.
Messages auto-populate; user can then click "Extract preferences" which hits mock data.

### lucide-react v1.20 note
Package.json lists lucide-react ^1.20.0. The actual published package at that range is
a valid release; all icons used (MapPin, Star, Car, Bed, etc.) are present in v1.x.

## Deviations from Spec

### No CalendarView day-column grid
The spec mentioned a "calendar view". Implemented as a horizontal Gantt-style bar chart
(one row per day, events as percentage-width bars) rather than a full week-column grid.
More space-efficient for a 2-day itinerary and avoids an external calendar library.

### No separate "EditConstraints" component
The spec implied a way to edit extracted constraints before generating. The
ExtractedPreferences screen shows all extracted values in a read-only table with
a "Generate itinerary →" CTA. Inline editing is deferred — the user can go back
via the "Start over" button in the header.
