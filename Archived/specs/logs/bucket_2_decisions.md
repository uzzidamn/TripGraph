## Unspecified Decisions Made During Build

### `_parse_llm_json` defined in `chat_parser.py` and imported by `constraint_validator.py`
The spec said each node should handle JSON parsing but didn't specify where the helper lives.
Placed in chat_parser.py and re-imported by constraint_validator.py to avoid duplication.

### Tool fallback is try/except Exception (not try/except ImportError)
The spec says "try real imports first, fall back to mock if ImportError." However, all tool
modules exist (Bucket 5 implemented them) — they fail at runtime if Neo4j is offline, not at
import time. Used `try/except Exception` around each tool call instead of around the import.

### `destination` field injected onto hotel/activity dicts after tool call
The Neo4j queries via `queries.py` don't return a `destination` field on hotel/activity nodes
(it's expressed as a graph edge, not a property). The `candidate_generator` filters hotels by
`h.get("destination") == destination`. Added `h.setdefault("destination", dest)` in the
data_retriever to ensure the filter works correctly with real Neo4j results.

### `route_id` field injected onto transport/waypoint dicts
Same reason as above — added `t.setdefault("route_id", route_id)` and similar for waypoints.

### Mock data in `data_retriever.py` only covers Rishikesh and Jaipur
The mock data in the spec (Section B.4) only provided Rishikesh examples. Extended to include
Jaipur mocks as well so the pipeline runs meaningfully when a heritage destination is requested.

### Prompt kept under ~400 tokens for explainer
Passed a summarised itinerary dict to the explainer rather than the raw itinerary. The raw dict
includes `trip_graph` (non-serializable) and is too long for the free-tier context. Summary
includes: destination, transport mode/tier, hotel name/price, total cost, activities list.

### `_main_app` and `_replan_app` compiled at module load time
The spec didn't specify when to compile. Compiled once at import time so first `run_workflow()`
call isn't slow. Each call to `run_workflow()` creates a fresh `initialize_state()`.

## Deviations from Spec

### `trip_graph` explicitly popped from `selected_itinerary` before storing in state
The spec mentions in pitfalls: "The trip_graph field contains dataclass instances — use
default=str in any json.dumps() call." Took the stricter approach: remove it from the
selected itinerary stored in state entirely, since it is never needed downstream (API layer
and frontend never use it). This avoids serialization issues at the FastAPI boundary.
