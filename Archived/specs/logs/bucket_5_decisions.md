## Bugs Fixed During Bucket 5

### Bug 1: `queries.py` — route dict missing `origin` field
**Problem**: `find_routes` and `full_route_data` projected route properties but did not include the origin city name. When Neo4j is live (not mock), `timeline_generator` called `route.get("origin")` and got `None`, producing "Drive from Origin" instead of "Drive from Gurugram".

**Fix**: Added `origin: origin.name` to all route projections:
```cypher
RETURN r {.*, origin: origin.name, destination: dest.name, ...} AS route
```

### Bug 2: `replanner_agent.py` — `changes` list lost before API response
**Problem**: `replan_itinerary()` returned `{"updated_itinerary": ..., "changes": [...], ...}`. The agent correctly extracted `changes` but stored only `updated_itinerary` in `replanned_itinerary` in TripState. The API route then called `replanned.pop("changes", [])` and always got `[]`.

**Fix**: Embed `changes` inside `replanned_itinerary` before returning from the node:
```python
return {
    "replanned_itinerary": {**updated_itinerary, "changes": changes},
    "replanning_explanation": explanation,
}
```
The API route's existing `pop("changes", [])` then correctly extracts it.

### Bug 3: `candidate_generator.py` — unused `from itertools import product`
**Problem**: Import was a leftover from an earlier design that used `itertools.product` for crossproduct generation. Not used in the final implementation.

**Fix**: Removed the import.

## Unspecified Decisions Made During Build

### Test suite skips neo4j import gracefully
When `neo4j` package is not installed (running outside the backend venv), Sections 1 and 3 fall back to file-existence + source inspection checks. This allows the test suite to run in CI or bare Python environments without the full dependency stack.

### `_ACTIVITIES` test fixture includes all 3 Rishikesh activities
The test mock data includes rafting, aarti, AND cafe hopping. This is required because `must_include: ["rafting", "cafes"]` in the constraints needs both to be present for the validator to pass. Initially only rafting and aarti were included, causing the "cafes" must_include check to fail.

### Replanner uses gap-preserving time shift
Events are shifted maintaining original gaps between them (not all shifted by the same absolute amount). The gap-preserving approach ensures hotel checkout, aarti timing, and other fixed-gap events stay realistic after a delay. Compression is applied first to recover slack before propagating any remaining delay as a shift.

### Timeline `_event` helper returns cost only when non-zero
`**({"cost": cost} if cost else {})` avoids serializing `"cost": 0` for travel/rest events, keeping the response payload compact.
