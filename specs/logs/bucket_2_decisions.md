## Unspecified Decisions Made During Build

1. **`_call()` helper in data_retriever.py** — Created a single helper function to handle the real→mock fallback pattern rather than repeating try/except for each of the 6 tools. Keeps the node logic clean.

2. **mock_tools.py includes Jaipur data** — Spec B.4 only showed Rishikesh mock data. Added Jaipur hotels, activities, transport, restaurants, and waypoints so both routes from MOCK_ROUTES are functional.

3. **`get_llm_json()` uses full provider branches** — Rather than falling through to `get_llm()` (which would double-count the rate limit), the function has explicit branches for all providers and calls `_wait_for_rate_limit()` once at the top.

4. **Conditional edge key `"__end__"` in LangGraph** — `StateGraph.add_conditional_edges()` with `END` as a target requires mapping `"__end__"` as a string key to the `END` sentinel. Used `{"retrieve_data": "retrieve_data", "__end__": END}`.

5. **`_DEST_TYPE_MAP` in constraint_validator.py** — Spec says to detect destination/destination_type mismatch but doesn't provide a lookup table. Built a static map of 14 known Indian destinations. Mismatches for unknown destinations are silently ignored (not a blocking conflict).

6. **`data_retriever_node` `_call()` signature** — Wrapped both real and mock references at module level; `_call()` receives the selected function reference rather than calling by name. This avoids re-evaluating `_NEO4J` on every call.

## Deviations from Spec

1. **`get_llm_json()` openai/ollama branches added** — Spec only showed Gemini and Claude branches with `return get_llm(run_name=run_name)` as fallback. That fallback would call `_wait_for_rate_limit()` a second time. Added explicit openai/ollama branches to keep rate limit accounting correct.

2. **`_build_messages()` defined per-node** — Spec suggests a shared helper. Each LLM-calling node defines its own `_build_messages()` to avoid cross-module imports. The function body is identical in all three nodes.
